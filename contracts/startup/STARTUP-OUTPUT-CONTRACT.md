# STARTUP-OUTPUT-CONTRACT.md — Startup Receipt Contract

**Version:** 1.0.0
**Status:** Canonical
**Last Updated:** 2026-07-24

---

## Purpose

This contract defines the format and requirements for startup receipts generated by Librarian Node implementations. It is platform-neutral and applies to Windows, Linux, and macOS nodes.

---

## Receipt Format

### JSON Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "Startup Receipt",
  "description": "Canonical startup receipt format for Librarian Nodes",
  "type": "object",
  "required": [
    "receipt_id",
    "node_id",
    "platform",
    "governance_commit",
    "startup_phase",
    "identity_loaded",
    "governance_verified",
    "capabilities_loaded",
    "environment_validated",
    "checks_passed",
    "checks_failed",
    "status",
    "timestamp"
  ],
  "properties": {
    "receipt_id": {
      "type": "string",
      "description": "Unique receipt identifier",
      "pattern": "^[A-Z0-9-]+$"
    },
    "node_id": {
      "type": "string",
      "description": "Unique node identifier",
      "minLength": 1
    },
    "platform": {
      "type": "string",
      "description": "Node platform",
      "enum": ["windows", "linux", "macos"]
    },
    "governance_commit": {
      "type": "string",
      "description": "Canonical governance commit SHA",
      "pattern": "^[a-f0-9]{40}$"
    },
    "startup_phase": {
      "type": "string",
      "description": "Current startup phase",
      "enum": ["complete", "failed"]
    },
    "identity_loaded": {
      "type": "boolean",
      "description": "Whether identity was loaded successfully"
    },
    "governance_verified": {
      "type": "boolean",
      "description": "Whether governance was verified successfully"
    },
    "capabilities_loaded": {
      "type": "boolean",
      "description": "Whether capabilities were loaded successfully"
    },
    "environment_validated": {
      "type": "boolean",
      "description": "Whether environment was validated successfully"
    },
    "checks_passed": {
      "type": "integer",
      "description": "Number of checks that passed",
      "minimum": 0
    },
    "checks_failed": {
      "type": "integer",
      "description": "Number of checks that failed",
      "minimum": 0
    },
    "status": {
      "type": "string",
      "description": "Node status after startup",
      "enum": ["GOVERNED_EXECUTION", "STARTUP_FAILED"]
    },
    "timestamp": {
      "type": "string",
      "description": "ISO-8601 timestamp of receipt generation",
      "format": "date-time"
    }
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `receipt_id` | string | Yes | Unique receipt identifier (format: `<PLATFORM>-STARTUP-<timestamp>`) |
| `node_id` | string | Yes | Unique node identifier |
| `platform` | enum | Yes | Node platform: `windows`, `linux`, or `macos` |
| `governance_commit` | string | Yes | Canonical governance commit SHA-256 |
| `startup_phase` | enum | Yes | Current startup phase: `complete` or `failed` |
| `identity_loaded` | boolean | Yes | Whether identity was loaded successfully |
| `governance_verified` | boolean | Yes | Whether governance was verified successfully |
| `capabilities_loaded` | boolean | Yes | Whether capabilities were loaded successfully |
| `environment_validated` | boolean | Yes | Whether environment was validated successfully |
| `checks_passed` | integer | Yes | Number of checks that passed |
| `checks_failed` | integer | Yes | Number of checks that failed |
| `status` | enum | Yes | Node status after startup: `GOVERNED_EXECUTION` or `STARTUP_FAILED` |
| `timestamp` | string | Yes | ISO-8601 timestamp of receipt generation |

## Validation Rules

### Receipt ID Format

Receipt IDs must follow the pattern: `<PLATFORM>-STARTUP-<timestamp>`

Examples:
- `WINDOWS-STARTUP-20260724-220000`
- `LINUX-STARTUP-20260724-220000`
- `MACOS-STARTUP-20260724-220000`

### Governance Commit Format

Governance commits must be valid SHA-256 hashes (40 hexadecimal characters).

### Status Transitions

```
UNREGISTERED → GOVERNED_NODE → GOVERNED_EXECUTION
                              ↘ STARTUP_FAILED
```

### Check Counts

- `checks_passed` + `checks_failed` must equal total checks executed
- Minimum total checks: 6 (identity, governance source, governance commit, governance contracts, capabilities, environment)

---

## Equivalence Rules

All platform implementations must produce receipts with identical deterministic fields:

**Deterministic Fields (Must Match):**
- `governance_commit`
- `identity_loaded`
- `governance_verified`
- `capabilities_loaded`
- `environment_validated`
- `checks_passed`
- `checks_failed`
- `status`

**Variable Fields (Expected to Differ):**
- `receipt_id` (different per platform)
- `node_id` (different per node)
- `platform` (different per platform)
- `timestamp` (different per execution)
